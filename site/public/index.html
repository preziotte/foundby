How it works

Scripts find the hosts. Your agent finds out what they are.

Mention trackers and backlink tools list hosts. They do not open each one, decide that this one is a Spanish setup tutorial worth a thank-you and that one is a parked domain never to be shown again, and write that into a file you own. That is the part that makes the report readable, and it is only cheap because the agent is already there.

01 · remembers

A ledger, not a dashboard

Every host, agent and platform ever seen, with first-seen date, kind and a note, in docs/foundby.md next to your code. Each run covers exactly the gap since the last one. Junk surfaces once.

02 · explains

One line per new host

The report ends with the hosts worth a look. The agent fetches each, searches for the page that links you, and records a kind and a one-line note. Hand edits in the markdown stick.

03 · stays yours

No service, no account

Runs on your machine with your credentials. State is two files in your repo. Client IPs are never read. Nothing is sent anywhere that you did not already pay for.

/foundby open turns the ledger into a page.

Every row ever seen, with its kind and note, plus a filter box, kind chips and sortable columns. It is a single HTML file rendered from the ledger in your repo. Click the chips below to try the filter.

Sources

A site with nothing but a domain gets the mention search. The rest are worth adding when you already have them.

Without an agent

The scripts run on their own.

Python 3.10+ and the standard library, plus cryptography if you wire GA. Config is one foundby.json in your repo. The agent's job is the lookup step: visiting each new host and writing the one-line note. Without one, you do that with set.

# install as plain files in this repo (the agent does the same)
git clone --depth 1 https://github.com/preziotte/foundby .claude/skills/foundby && rm -rf .claude/skills/foundby/.git

# write foundby.json, then check which sources are wired
python3 .claude/skills/foundby/scripts/foundby.py init example.com
python3 .claude/skills/foundby/scripts/foundby.py doctor

# fetch, fold into docs/foundby.md, print what is new (scratch dir holds the raw pulls)
python3 .claude/skills/foundby/scripts/foundby.py run /tmp/foundby

# record what a new host turned out to be
python3 .claude/skills/foundby/scripts/foundby.py set annika.dev --kind blog --note "Personal blog, links from an inner page"

# open the ledger viewer
python3 .claude/skills/foundby/scripts/foundby.py view

# update the skill in place
python3 .claude/skills/foundby/scripts/foundby.py update
FAQ
What will the prompt actually do to my repo?

Your agent fetches foundby.dev, which points it at the GitHub repo and SKILL.md. It clones the skill into .claude/skills/foundby as plain files (no nested git repo), asks whether you want the YouTube description search, writes a foundby.json with your domain, runs doctor to see which sources you already have credentials for, and asks before wiring any that need setup. Then it runs the first report and writes the ledger to docs/foundby.md. Every step is a plain Python script you can read first.

Can I install it by hand, or use it without an agent?

Yes to both. The clone command under Without an agent is the manual install, and the same scripts run from a shell with no agent at all. To install it once for every project instead, clone anywhere and symlink the clone into ~/.claude/skills/foundby.

What does this see that Google Analytics does not?

Pages that mention your site whether or not anyone clicked (Hacker News, GitHub, Bluesky, YouTube descriptions), link previews fired when someone pastes your URL into Slack, Discord or iMessage, AI assistants fetching a page to answer a question, and referring pages rather than just hosts. It also reads GA itself, so you get the union.

Is anything sent to a server?

No. There is no foundby service. The scripts run on your machine, call the public APIs and your own analytics and log bucket with your credentials, and write two files into your repo. Client IPs are never read from logs.

Do I need Google Analytics or CDN logs?

No. A site with only a domain gets the mention search. GA4, CloudFront logs and Bing backlinks are optional and each one adds a layer. doctor looks at what you have and says which would add the most.

Why does an agent need to be involved?

The scripts find new hosts. The agent fetches each one and decides what it is: a tutorial worth a thank-you, a directory that listed you, a parked domain never to be shown again. That one-line note is what makes the ledger readable, and it is only cheap because the agent is already there.

What about AI agents crawling my site?

foundby records the live-fetch agents, because a person was behind each one. For crawlers, training bots and the full picture of what AI agents do on your site, use agenttraffic, which reads the same logs. foundby is about people; agenttraffic is about agents.

How do I get new versions?

Every /foundby run first checks GitHub for a newer version (one request for a six-byte file; nothing about you is sent, and "check_updates": false in foundby.json turns it off). If there is one, the agent says so and offers to update before running. /foundby update, or foundby.py update from a shell, applies it in place: a git pull if the skill is a clone, otherwise the GitHub tarball unpacked over the skill files. Your config and ledger are never touched, and the ledger carries a schema number so an older one is migrated forward.

How accurate are the hit counts?

They are a magnitude, not a count: edge hits plus GA sessions overlap. The point of the ledger is the first-seen date and the note, not the number.
